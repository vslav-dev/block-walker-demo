# 06 — Переход на Angular (22.10.2026)

Переписать демо с «голый JS + three.js» на общую архитектуру остальных игр в `GAMES` (x-scheme, unscripted, megagame-factory): Angular держит состояние, компоненты и HTML; движок рисует под ними. Phaser там — здесь three.js.
Старые планы 00–05 — история. Пути файлов в них — прежние (JS); соответствие старое → новое ниже.

## Решения

- Копия старого кода — `block-walker-demo-archive/` (в `.gitignore`). Рабочая папка переписана на месте.
- Стек как у соседей: Angular 21, standalone, zoneless, OnPush, signals, TypeScript strict, SCSS, vitest через `ng test`.
- Без Tailwind и без router: соседи их не используют, маршрутов нет.
- Граница — главное решение:
  - `src/game` — движок: мир, физика, камера, свет, рендер. Ноль импортов Angular. Тестируется без браузера.
  - `src/app` — Angular: компоненты, сервисы-состояние, вся разметка и стили.
  - Движок получает снаружи только `GameHost`: живые настройки игрока и живые настраиваемые числа. Читает их каждый кадр.
  - Движок отдаёт наружу только показания (`readouts`) для панели.
- Состояние живёт в сервисах-синглтонах на signals (как `debugState`/`viewState` у соседей), не в движке.
- Движок собран как «корень композиции + пошаговый кадр»: `Game` создаёт подсистемы и вызывает их в фиксированном порядке. Никаких ECS и шины событий — оверинжиниринг.

## Структура

`src/game` — по фичам, не по слоям:
- `game.ts` — корень композиции, цикл кадра, жизненный цикл (создать, пауза, уничтожить).
- `game-host.ts`, `settings.ts`, `tuning.ts`, `config.ts`, `readouts.ts` — контракт с внешним миром и константы движка.
- `core/` — углы, реестр настраиваемых чисел.
- `world/` — блоки, воксельный мир, генератор. Чистые данные.
- `character/` — тело игрока (физика), ориентация корпуса, модель робота.
- `input/` — клавиатура, мышь, колесо, захват указателя.
- `aim/` — режим прицела (логика) и красная линия.
- `camera/` — зум и камера.
- `daylight/` — цикл суток (числа) и небо со светом.
- `world-view/` — отрисовка мира: слои, стены, видимость зданий, маяки дверей.

`src/app`:
- `services/` — состояние: игра (жизненный цикл, пауза, статус), настройки игрока, настраиваемые числа, режим панели отладки.
- `components/` — холст игры, статус, кнопка и экран настроек, панель отладки (оболочка, раздел, элемент управления числом).

## Соответствие старое → новое

- `main.js` → `game/game.ts` (цикл, сборка) + `app/services/game.service.ts` (запуск, статус, новый мир) + `readouts.ts` (показания).
- `index.html` (разметка и стили) → компоненты `app/components/*` и их `.html/.scss`.
- `debug-panel.js` → `debug-panel`, `debug-section`, `tunable-control` + `debug.service.ts`.
- `settings-screen.js`, `settings.js` → `settings-screen`, `settings-button` + `settings.service.ts`, `game/settings.ts`.
- `tunables.js` → `game/core/tunables.ts` (реестр) + `tunables.service.ts` (обёртка на signals).
- `world-view.js` → `world-view/` (`world-view`, `building-visibility`, `layer-geometry`, `layer-types`, `wall-parts`).
- Остальные модули переехали 1:1 в свою фичу-папку, добавлены типы.
- Тесты `test/*.test.js` → `*.spec.ts` рядом с кодом, vitest.

## Отличия от оригинала (осознанные)

- Новый мир по `R` — пересоздание игры без перезагрузки страницы; `?seed=` в адресе обновляется. Раньше — перезагрузка.
- Время суток при новом мире не сбрасывается на значение по умолчанию (раньше сбрасывалось побочным эффектом перезагрузки).
- Цикл кадра стартует до загрузки робота; робот появляется, когда загрузится. Раньше мир не рисовался до загрузки.
- `R` с Ctrl/Cmd/Alt и автоповтор клавиши игнорируются.
- Размер холста и ввод по-прежнему от окна целиком (игра на весь экран).
- Остальное поведение — без изменений: перенос механический, числа и порядок шагов кадра сохранены.
